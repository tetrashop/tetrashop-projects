## 📄 چکیده

پروژهٔ `tetrashop-projects` یک **مونورپو**ی بزرگ است که یک فروشگاه اینترنتی کامل (محصولات فیزیکی و دیجیتال) را به‌همراه **ده‌ها سرویس جانبی** – شامل ربات‌های پیام‌رسان، موتورهای شطرنج، سامانه‌های پردازش زبان طبیعی، تشخیص گفتار، OCR، ابزارهای مالی و پنل‌های مدیریتی – در خود جای داده است.  
هدف این مخزن ایجاد یک **اکوسیستم یکپارچه** برای عرضهٔ کالاهای نرم‌افزاری و سخت‌افزاری، همراه با **واسط‌های کاربری پیش‌نمایش (دموهای تعاملی)** و قابلیت فروش مستقیم می‌باشد.

این مستند **تمامی جنبه‌های فنّی**، چالش‌های پیش‌آمده در فرایند توسعه، راه‌حل‌های اعمال‌شده و دستورالعمل‌های راه‌اندازی را به‌صورت علمی تشریح می‌کند. همچنین برای **تک‌تک محصولات دیجیتال** مستندات جداگانه‌ای ارائه می‌دهد که در پوشهٔ مربوطه نیز موجود است و در این راهنما به‌صورت خلاصه گردآوری شده‌اند.

## ۱. مقدمه

این مخزن حاصل **ادغام پروژه‌های مجزّا** (فروشگاه، ربات‌ها، NLP، شطرنج و …) در یک ساختار یکپارچه است.  
بخش اصلی فروشگاه با **Next.js 16** و **Tailwind CSS** پیاده‌سازی شده و از **Zustand** برای مدیریت حالت سبد خرید استفاده می‌کند.  
محصولات دیجیتال شامل **بیش از ۳۰ پروژهٔ مستقل** هستند که برای هرکدام یک **دموی تعاملی** در فروشگاه تعبیه شده است. هر محصول دیجیتال دارای یک **README تحلیلی** می‌باشد که جزئیات فنّی، چالش‌ها و راه‌حل‌های اختصاصی خود را توصیف می‌کند.

## ۴. چالش‌ها و راه‌حل‌های فنّی

### ۴.۱ خطای Hydration Mismatch

- **مشاهده:** استفاده از `toLocaleString()` برای نمایش قیمت، خروجی متفاوتی در سرور (`3,500,000`) و مرورگر (`۳٬۵۰۰٬۰۰۰`) تولید می‌کرد.
- **تحلیل:** عدم تطابق DOM سمت سرور و کلاینت به دلیل وابستگی تابع به لوکیل محیط اجرا.
- **راه‌حل:** تعریف تابع `formatPrice` با `Intl.NumberFormat('fa-IR')` که خروجی یکسانی در هر دو محیط ارائه می‌دهد.

### ۴.۲ خطای Watchpack (EACCES) در Termux

- **مشاهده:** Next.js در Termux خطای `EACCES: permission denied, watch '/data'` صادر می‌کرد.
- **علّت:** Webpack تلاش می‌کرد کل فایل‌سیستم را برای تغییرات پایش کند، امّا به پوشه‌های سیستمی دسترسی نداشت.
- **راه‌حل:** در `next.config.mjs` گزینهٔ `watchOptions.ignored` برای نادیده گرفتن `/data` و `node_modules` تنظیم شد. همچنین از پرچم `--webpack` برای دور زدن Turbopack استفاده گردید.

### ۴.۳ ناسازگاری ESM / CommonJS

- **مشاهده:** فایل `package.json` با `"type": "module"` تعریف شده بود، امّا فایل‌های پیکربندی از `module.exports` استفاده می‌کردند → `ReferenceError: module is not defined`.
- **راه‌حل:** تبدیل تمام فایل‌های پیکربندی به `export default` و استفاده از پسوند `.cjs` برای اسکریپت‌های موقّتی که نیاز به `require` داشتند.

### ۴.۴ اشغال پورت و مدیریت پروسه‌ها

- **مشاهده:** خطای `EADDRINUSE` هنگام اجرای مکرّر `npm run dev`.
- **راه‌حل:** کشتن پروسه‌های قدیمی با `pkill -9 node`، تغییر پورت پیش‌فرض به `3002` و بررسی آزاد بودن پورت با `nc`.

### ۴.۵ مشکل زیرماژول‌های گیت

- **مشاهده:** خطای `fatal: not a git repository: apps/frontend/...` هنگام `git add`.
- **راه‌حل:** غیرفعال‌سازی و حذف ساب‌ماژول‌های خراب با `git submodule deinit`، پاک‌سازی `.gitmodules` و `.git/modules`.

### ۴.۶ یکپارچه‌سازی محصولات دیجیتال

- **چالش:** ۳۰+ پروژهٔ مستقل می‌بایست به‌عنوان محصول در فروشگاه نمایش داده شوند.
- **راه‌حل:** اسکریپت `build-inventory.cjs` کلیهٔ پوشه‌ها را اسکن و فایل `digitalProducts.json` را تولید می‌کند. برای هر پروژه README حداقلی ساخته شد و در صفحهٔ `/digital-products` به‌صورت پویا بارگذاری می‌شوند.

### ۴.۷ ساخت دموهای تعاملی

- **چالش:** هر محصول دیجیتال نیاز به پیش‌نمایش تعاملی پیش از خرید داشت.
- **راه‌حل:** برای هر دسته (ربات، شطرنج، NLP، OCR، گفتار، مالی، پلتفرم) یک کامپوننت React جداگانه ساخته شد. با استفاده از `dynamic import` (با `ssr: false`) بارگذاری سمت کلاینت انجام شد و مؤلّفهٔ `DemoComponents` بر اساس شناسهٔ محصول، دموی مناسب را انتخاب می‌کند.

## ۵. راه‌اندازی پروژه

### پیش‌نیازها

- **Node.js** نسخهٔ ۱۸ یا بالاتر (در Termux: `pkg install nodejs`)
- **npm** یا **yarn**
- (اختیاری) **Python 3.9+** برای اجرای ربات‌ها و سرویس‌های هوش مصنوعی

### نصب و اجرای فروشگاه

```bash
cd ~/tetrashop-projects/frontend
npm install
npm run dev
```

فروشگاه روی http://localhost:3002 در دسترس خواهد بود.

ساخت نسخهٔ تولید

```bash
npm run build
npm start
```

۷. اسکریپت‌های خودکار (Automation)

در طول توسعه، اسکریپت‌های زیر برای خودکارسازی فرایندها تهیه شده‌اند:

· final_full.sh – نصب پکیج‌ها، تولید محصولات دیجیتال، ساخت دموها، رفع خطاهای پیکربندی و اجرای پروژه.

برای اجرای یک‌بارهٔ همهٔ مراحل کافی است اسکریپت مناسب را اجرا کنید:

```bash
cd ~/tetrashop-projects/frontend
chmod +x final_full.sh
./final_full.sh
```

۹. جمع‌بندی و چشم‌انداز

پروژهٔ TetraShop Projects اکنون یک بستر کامل برای فروش کالاهای فیزیکی و دیجیتال است.
با استفاده از معماری مدرن Next.js و مدیریت حالت Zustand، تجربهٔ کاربری روان و بدون خطا ارائه می‌شود.
دموهای تعاملی به خریداران کمک می‌کند پیش از خرید، محصولات نرم‌افزاری را آزمایش کنند.

در آینده می‌توان قابلیت‌های زیر را افزود:

· اتصال به درگاه پرداخت واقعی (زرین‌پال، Pay.ir)
· احراز هویت کاربران (NextAuth.js)
