## 📄 چکیده

پروژهٔ `tetrashop-projects` یک مونورپوی بزرگ است که در آن یک فروشگاه اینترنتی کامل (محصولات فیزیکی و دیجیتال)، به‌همراه ده‌ها سرویس جانبی شامل ربات‌های پیام‌رسان، موتورهای شطرنج، سامانه‌های پردازش زبان طبیعی، تشخیص گفتار، OCR، ابزارهای مالی و پنل‌های مدیریتی تجمیع شده‌اند.  
هدف این مخزن ایجاد یک اکوسیستم یکپارچه برای عرضهٔ محصولات نرم‌افزاری و سخت‌افزاری، همراه با واسط‌های کاربری پیش‌نمایش (دموهای تعاملی) و قابلیت فروش مستقیم است.

این مستند تمام جنبه‌های فنی، چالش‌های پیش‌آمده در فرایند توسعه، راه‌حل‌های اعمال‌شده و دستورالعمل‌های راه‌اندازی را به‌صورت علمی تشریح می‌کند.

## ۱. مقدمه

این مخزن حاصل ادغام چندین پروژهٔ جداگانه (فروشگاه، ربات‌ها، NLP، شطرنج و …) در یک ساختار واحد است.

## ۴. چالش‌ها و راه‌حل‌های فنی (Scientific Approach)

### ۴.۱ خطای Hydration Mismatch

**مشکل:** هنگام استفاده از `toLocaleString()` برای نمایش قیمت، سرور (Node.js) خروجی متفاوتی با مرورگر (مثلاً `3,500,000` در مقابل `۳٬۵۰۰٬۰۰۰`) تولید می‌کرد و React خطای Hydration می‌داد.  
**تحلیل:** این خطا به‌دلیل عدم تطابق DOM سمت سرور و کلاینت رخ می‌دهد. تابع `toLocaleString` وابسته به محیط اجرا است و `Intl` در Node.js ممکن است لوکیل متفاوتی اعمال کند.  
**راه‌حل:** یک تابع فرمت‌کنندهٔ یکتا (`formatPrice`) با `Intl.NumberFormat('fa-IR')` تعریف شد که صراحتاً لوکیل فارسی را تنظیم می‌کند و در هر دو محیط خروجی یکسانی دارد.

### ۴.۲ خطای Watchpack (EACCES) در Termux

**مشکل:** در محیط Termux (اندروید)، Next.js هنگام اجرا خطاهای `Error: EACCES: permission denied, watch '/data'` صادر می‌کرد.  
**علت:** Webpack تلاش می‌کند کل فایل‌سیستم را برای تغییرات مانیتور کند، اما به پوشه‌های سیستمی دسترسی ندارد.  
**راه‌حل:** در `next.config.mjs` گزینهٔ `watchOptions.ignored` به‌گونه‌ای تنظیم شد که پوشه‌های `/data` و `node_modules` را نادیده بگیرد. همچنین از `--webpack` برای دور زدن Turbopack استفاده کردیم (چون Turbopack از معماری ARM64 پشتیبانی بومی ندارد).

### ۴.۳ ناسازگاری ESM / CommonJS

**مشکل:** فایل `package.json` دارای `"type": "module"` بود، اما بعضی فایل‌های پیکربندی (مانند `next.config.js` و `tailwind.config.js`) با `module.exports` نوشته شده بودند که خطای `ReferenceError: module is not defined` می‌داد.  
**راه‌حل:** تمام فایل‌های پیکربندی به فرمت استاندارد ES Module تبدیل شدند (`export default`) و فایل‌های قدیمی `require` حذف گردیدند. برای فایل‌های موقت (مانند `build-inventory.cjs`) از پسوند `.cjs` استفاده شد.

### ۴.۴ اشغال پورت و مدیریت پروسه‌ها

**مشکل:** هنگام اجرای مکرر `npm run dev`، خطای `EADDRINUSE` رخ می‌داد (پورت ۳۰۰۱ اشغال).  
**علت:** پروسهٔ قبلی Next.js به‌درستی متوقف نشده بود یا با `Ctrl+Z` معلق مانده بود.  
**راه‌حل:**  
- استفاده از دستور `pkill -9 node` برای کشتن همهٔ پروسه‌های Node متعلق به کاربر.  
- تغییر پورت پیش‌فرض به ۳۰۰۲ در اسکریپت `package.json` برای جلوگیری از تداخل.  
- افزودن یک بررسی ساده با `nc` برای اطمینان از آزاد بودن پورت.

### ۴.۵ مشکل زیرماژول‌های گیت

**مشکل:** هنگام `git add` خطای `fatal: not a git repository: apps/frontend/../../.git/modules/apps/frontend` ظاهر می‌شد.  
**علت:** یک زیرماژول گیت از قبل وجود داشت که مخزن آن حذف شده بود، اما ارجاع در `.gitmodules` و `.git` باقی مانده بود.  
**راه‌حل:**  
- غیرفعال‌سازی زیرماژول با `git submodule deinit -f`  
- حذف پوشهٔ داخلی `.git/modules/apps/frontend`  
- پاک‌سازی `.gitmodules` و `git rm --cached` مسیر مشکل‌دار.  
- در نهایت، انتقال فیزیکی پوشهٔ مشکل‌دار به یک نام موقت برای دور زدن محدودیت.

### ۴.۶ یکپارچه‌سازی محصولات دیجیتال

**چالش:** ۳۰+ پروژهٔ مستقل (Python, Node, PHP) باید در فروشگاه به‌عنوان محصول قابل خرید نمایش داده می‌شدند.  
**راه‌حل:**  
- یک اسکریپت Node.js (`build-inventory.cjs`) تمام پوشه‌ها را اسکن کرده و فایل `digitalProducts.json` را تولید می‌کند.  
- برای هر محصول یک فایل `README.md` حداقلی تولید شد و در صورت نبودن، به‌طور خودکار ایجاد گردید.  
- در صفحۀ `/digital-products`، لیست محصولات از JSON بارگذاری و با `Link` به صفحهٔ جزئیات هدایت می‌شود.

### ۴.۷ ساخت دموهای تعاملی

**چالش:** هر پروژهٔ دیجیتال باید یک پیش‌نمایش تعاملی در فروشگاه داشته باشد تا کاربر پیش از خرید آن را آزمایش کند.  
**راه‌حل:**  
- برای هر دسته (ربات، شطرنج، NLP، OCR، گفتار، مالی، پلتفرم) یک کامپوننت React جداگانه ساخته شد.  
- از `dynamic import` (با `ssr: false`) در Next.js استفاده شد تا بارگذاری سمت کلاینت باشد و با خطای SSR تداخل نکند.  
- کامپوننت `DemoComponents` بر اساس شناسهٔ محصول، دموی مناسب را انتخاب و نمایش می‌دهد.

## ۵. راه‌اندازی پروژه

### پیش‌نیازها

- **Node.js** نسخه ۱۸ یا بالاتر (در Termux: `pkg install nodejs`)
- **npm** یا **yarn**
- (اختیاری) Python 3.9+ برای اجرای ربات‌ها و سرویس‌های هوش مصنوعی

### نصب و اجرای فروشگاه

```bash
# ۱. ورود به پوشهٔ فرانت‌اند
cd ~/tetrashop-projects/frontend

# ۲. نصب وابستگی‌ها
npm install

# ۳. اجرای پروژه در حالت توسعه
npm run dev

# فروشگاه روی http://localhost:3002 در دسترس خواهد بود
```

ساخت نسخهٔ تولید

```bash
npm run build
npm start
```

۷. اسکریپت‌های خودکار (Automation)

در طول توسعه چندین اسکریپت Bash تهیه شد که عملیات تکراری را خودکار می‌کنند:

· final_full.sh: نصب پکیج‌ها، تولید محصولات دیجیتال، ساخت دموها، رفع خطاهای پیکربندی و اجرای پروژه.
· master-setup.sh: نسخهٔ کامل‌تر با قابلیت resume در صورت شکست.
· build-inventory.cjs: اسکن پوشه‌ها و ساخت فایل JSON محصولات دیجیتال.

برای اجرای یک‌بارهٔ تمام مراحل کافی است فایل مربوطه را اجرا کنید:

```bash
cd ~/tetrashop-projects/frontend
chmod +x final_full.sh
./final_full.sh
```

پروژهٔ TetraShop Projects اکنون یک بستر کامل برای فروش کالاهای فیزیکی و دیجیتال است.
